# Talvix API to UI mapping

## Contract assumptions

- **Implemented API root:** `/api/v1` from [`../../backend/src/routes/index.js`](../../backend/src/routes/index.js). Public health is `GET /health` relative to that root.
- Access-protected calls use an in-memory `Authorization: Bearer <access-token>`. Cross-origin register, login, refresh and logout use `credentials: 'include'` so the browser accepts, rotates and clears the HttpOnly refresh cookie. Ordinary bearer-only calls omit credentials unless deployment policy changes. Never expose the cookie to application code; refresh is single-flight and each eligible request is replayed at most once.
- The Express error handler returns structured application errors, but the frontend must normalize unknown/network/validation failures into `{ status, code?, message, fieldErrors?, correlationId? }` without displaying internals.
- Treat backend DTOs as transport data. Parse at the boundary and map into role-specific view models. Never spread arbitrary response fields into views, analytics or logs.
- List endpoints have validator-specific pagination/filter contracts; adapters normalize them to `{ items, page, pageSize, total, totalPages }` only after inspecting actual response fixtures.

## DTO and adapter rules

Create independent adapters such as `CandidateOfferDto -> CandidateOfferViewModel` and `ManagedOfferDto -> ManagedOfferViewModel`; never use CSS hiding to conceal recruiter-only fields. Use exhaustive mappings for statuses, permissions, document scan/download state, date fields and monetary visibility. Unknown enums render a safe neutral state and generate sanitized diagnostics. Keep IDs opaque.

Normalize Zod/server validation errors to form fields plus an error summary. Preserve the user’s safe draft after `422`; for `409`, retain draft, refetch authoritative state and present an explicit reconcile/retry action. A `404` on scoped resources is not proof that the entity never existed; use generic not-found/unavailable copy.

## Notification action URL compatibility

Backend-persisted URLs are an implemented contract. The frontend canonical workspace remains `/org/*`, but Phase 1 must register guarded aliases that parse an opaque 24-character ID, evaluate the destination guard, and replace-history redirect without carrying unapproved query parameters.

## Query and mutation behavior

- Query keys: `[domain, actorId, companyId?, scope, filters]`; abort obsolete search requests; keep URL filters canonical.
- After membership/profile/company mutations, invalidate session context, company and navigation capability queries.
- After workflow commands, invalidate entity detail, list, pipeline/analytics and linked application; do not optimistically invent server transitions.
- Keep upload payloads out of caches. Use multipart request progress only if the selected client mechanism supports it; cancel/retry must create a fresh request. Fetch downloads just in time and revoke object URLs.
- Timers display server-derived deadlines and tolerate clock skew; server outcome wins.

## Recruiter dashboard composition

The approved screen would currently require, at minimum, managed jobs, application pipeline/statistics/list, interview calendar/analytics and offer analytics/approvals calls, each with potentially different permission and date semantics. That fan-out cannot guarantee the four KPI cards and pipeline represent one consistent snapshot. A backend aggregate should return an `asOf`, UTC range, permission-filtered metrics, pipeline stages and bounded attention items.

There is no AI endpoint. The application pipeline/skill match are deterministic and may support factual labels, but they do not authorize “AI match” scores or generated recommendations. Exact visual parity is therefore **Gap**; foundation work can proceed without it.
